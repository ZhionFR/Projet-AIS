- utiliser dig et nslookup : comment se configure la priorisation dans la config de nom de domaine sur linux
    - /etc/resolv.conf priorise les resolvers et dig/nslookup permettent d'interroger un resolver précis en bypassant ca

- boots attestés et rootkit eBPF
    - boot attesté : chaque couche (uefi, bootloader, kernel) check la couche suivante avant de l'executer; Secure boot = meme chose + signature
    - rootkit eBPF : abuse des hooks eBPF pour se faire passer pour un service légitime, plus dur a detecter/prévenir car eBPF est utilisé largement (mitigé par signature des programmes eBPF)

- socket comme objet systemd
    - systemd écoute a la place du service et retransmets 

- cas d'usage pour socket-activated et ce qu'est un socket du point de vue de systemd
    - lazy start pour économiser des ressources
    - permet aussi de boot plus vite (parrallelisme) le dependant car il n'attend pas que le service soit up (juste le socket)
    
- IAM, IDP et fédération
    - IAM : Identity and access management = gestion de comptes, roles, acces, cycle de vie
    - IdP : Identity provier = authentifie l'user et assertion d'identité (MFA par exemple)
    - fédération : un service provider authorise un IdP pour authentifier ses users

- PKCS12
    - conteneur binaires contenant certificat + clé privée + chaine de CA. protégé par mdp, utilisé pour transporter une identité TLS
 
- ce qu'est 802.1X et le lien avec les PKI
    - je savais bien que je connaissais : cf. RADIUS
    - réseau bloqué tant que l'authN n'a pas réussi (sauf traffic pour verification d'identité)
        - EAP-TLS le fait par TLS -> clé PKI 

- contexte utilisation RED et USE (online/offline processing) et les metriques pour du batch
    - RED/USE pour traffic online (car fait pour requetes/latence)
    - batch/offline : job/temps; avg. queue; failrate; 
        - USE reste vite fait pertinent en offline, RED non 

- ce qu'est un alias dans PfSense
    - c'est un alias... il y a une page "alias" pour attribuer un alias a une adresse IP (différent du DNS), un port ou une URL

- DNS split horizon
    - renvoie une réponse différente selon la source de la requete, typiquement interne/externe

- Open Telemetry
    - standard unifiant la collecte de metriques et logs idépendant du backend de stockage (grafana, prometheus,...)

- Est ce que le bastion peut/doit gérer le SSO
    - Non. Bastion = point de rebond pour admin
    - c'est un IdP qui fait le SSO qui se trouve en amont du bastion pour que les admins se log via le SSO aussi
